## 1. 宗旨与定位

上岸鸭不是普通待办清单，而是以真实任务为中心的 AI 个人执行教练。

核心闭环：

目标明确 → 任务拆解 → 设定验收标准 → 按真实精力排期 → 开始执行 → 识别卡点 → AI 解卡 → 提交成果与证据 → AI 按标准逐项验收 → 用户确认 → 保存记录 → 更新下一次计划。

解决的问题：
- 知道目标，却不知道每一步具体怎么做。
- 计划写得完整，实际时间和精力却不匹配。
- 做题、学习、开发时遇到困难后反复死磕。
- 只打开课程、只运行代码、只口头汇报，却被误认为完成。
- 任务做完了，却没有可核验成果或提交凭证。

产品原则：
1. 口头汇报不能直接变成已完成。
2. 计时投入不等于成果完成。
3. AI 生成内容不能冒充用户真实产出。
4. 不同任务类型必须使用不同验收标准。
5. 摄像头默认关闭，不能以人脸朝向判断理解程度。
6. 硬截止、固定事务、睡眠和休息优先于可移动任务。
7. 不确定、缺材料、无法读取时明确显示未知或失败，不得假装成功。
8. 保留 V8 原任务、历史数据、四象限和导航；升级采用兼容迁移，不清空旧数据。

页面清单：手机号注册/登录、首次设置密码、今日驾驶舱、任务详情和验收标准、新建任务、每日清单、四象限、截止雷达、精力排期、任务计时、卡壳诊断、提交证据、AI 验收报告、课程学习、拍照做题、错题本、资料中心、微信收集、验收中心、历史复盘、个人设置。

## 4. 手机号账号体系（P0，先于业务页面）

### 4.1 首次注册流程

1. 输入手机号（默认中国大陆 +86，预留其他国家区号）。
2. 点击获取验证码。
3. 服务端调用真实短信服务商发送验证码。
4. 用户输入短信验证码，服务端验证成功。
5. 服务端签发短时、一次性的注册凭证。
6. 用户进入设置密码页，输入密码并再次确认。
7. 服务端创建唯一手机号账号、保存密码哈希并建立登录会话。
8. 进入今日驾驶舱。

### 4.2 后续登录流程

1. 输入手机号。
2. 输入密码。
3. 服务端验证密码；正确则登录，错误必须拒绝。
4. 忘记密码时重新短信验证，再设置新密码。

### 4.3 安全规则

- 手机号标准化后建立 UNIQUE 唯一约束；一个手机号只能对应一个账号和一个当前密码凭证。
- 密码不得明文保存；可沿用现有 scrypt 密码哈希能力。
- 验证码仅保存哈希，不保存明文；有效期建议 5 分钟，最多尝试 5 次。
- 同手机号发送间隔至少 60 秒，并按手机号、IP、设备设置日限额和速率限制。
- 验证码验证成功后签发一次性注册票据，绑定手机号、用途和过期时间，成功使用后立即作废。
- 登录会话使用服务端 HttpOnly、Secure、SameSite Cookie；退出时服务端撤销会话。
- 密码错误提示统一，防止账号枚举；登录失败采用渐进限流。
- 找回密码必须重新短信验证；可按安全策略撤销旧会话。
- 生产环境禁止测试验证码、万能验证码、前端本地模拟登录。
- 短信供应商密钥只存放在服务端环境变量/密钥管理器，不得写进小程序包、前端 JS、Git 仓库或聊天记录。
- 手机号属于个人信息；必须说明收集目的、保存期限、用户权利和注销流程。

### 4.4 API 契约建议

| API | 用途 |
|---|---|
| POST /api/auth/sms/send | 发送短信验证码，返回 request_id、expires_in、retry_after |
| POST /api/auth/sms/verify | 验证短信验证码，返回一次性 registration_ticket |
| POST /api/auth/register | 使用 ticket＋密码创建账号 |
| POST /api/auth/login | 手机号＋密码登录 |
| POST /api/auth/password/reset | 短信验证后重设密码 |
| POST /api/auth/logout | 撤销当前会话 |
| GET /api/auth/me | 返回当前账号、脱敏手机号和绑定状态 |

短信服务使用 Provider Adapter，优先接入具备中国大陆短信资质的服务商（例如腾讯云短信）。供应商账号、签名、模板、密钥和可发送资质须由账号持有人在控制台配置。未配置时显示“短信服务未就绪”，不能伪造发送成功。

### 4.5 V8 旧账号兼容

- 不删除 V8 旧用户、任务、任务 ID、历史计时、资料和本地数据。
- 旧账号首次升级时，先登录旧账号，再绑定并验证手机号，随后设置密码；phone_e164 关联到原 user_id。
- 绑定时检查手机号唯一性；冲突必须阻断并人工处理，禁止自动合并两份数据。
- 迁移前备份数据库；迁移后核对用户任务数量、任务 ID、计时记录和附件引用。
- 未绑定手机号的旧账号保留兼容入口，不能静默锁死旧数据。

## 5. 任务创建：先定成果，再定计划

新建任务填写：任务名称、类型、目标、硬/软截止时间、固定时间、并行关系、前置依赖、熟练程度、预计耗时、当前精力、子任务、最终交付物、必要验收标准、证据类型和来源。

AI 可以生成验收标准草案，但用户确认后冻结为版本 1。任务完成后修改标准必须生成新版本并保留旧版本，不能为让任务通过而静默降低标准。

## 6. AI 真实验收系统

流程：创建任务 → 确认标准 → 执行 → 提交证据 → AI 识别 → 逐条对照 → 输出结论 → 用户确认/人工复核 → 保存审核记录。

状态：未开始、执行中、卡壳中、待提交证据、待 AI 验收、部分通过、验收通过、验收失败、无法核验、人工确认。

规则：
- 全部必要标准满足才能标记验收通过。
- 总分不能抵消硬性条件缺失。
- 用户点击完成或口头声称完成不能直接通过。
- 证据模糊、权限不足、内容不相关时标记无法核验或失败，并说明下一步。
- AI 生成的 Demo、截图、代码不能标记为用户真实成果。

任务类型模板：
- 课程：课程进度截图＋笔记关联＋知识测试＋作业。
- 做题：原题 OCR 确认＋用户解题过程＋逐题批改＋错题订正。
- 考研：真实学习记录＋主动回忆＋复习测试＋错题。
- 管理会计：真实课件读取＋知识解释＋练习计算＋错题订正。
- TRAE 课程：回放进度＋笔记＋实操＋作业＋测试。
- TRAE 原型：可访问 Demo/真机二维码＋页面截图＋开发过程截图＋Session ID＋微信后台版本/审核凭证。
- Agent PPT：可打开文件＋比赛要求覆盖＋项目真实截图＋演示＋提交凭证。
- Agent 智能体：输入输出契约＋真实工具调用＋异常处理＋运行日志＋可复现演示。
- 运营：作品链接＋发布时间＋平台后台数据截图；无链接不得标记已发布。

## 7. 反死磕与动态排期

- 对比预计耗时和实际耗时；超过阈值后询问是否卡住。
- 连续两轮检查无新产出或新证据时触发诊断。
- 识别目标不清、上下文不足、技术错误、资料缺失、精力不足五类卡点。
- AI 给出具体动作：缩小范围、换方法、补资料、演示操作、保存断点、休息后继续、调整时间或暂停。
- 排期先锁定固定事务和硬截止，再保护长期主线，最后安排可移动任务。
- 只在真实可并行时允许重叠；注意力任务不能被错误标记为并行。
- 根据真实历史耗时校准估时，不强行假设每次一定更快。
- 休息、吃饭、通勤、发呆、看剧、睡眠是日程的一部分，不作为失败。
- 摄像头默认关闭；主动授权后仅作为离开/中断辅助，不作为学习成果证明。

## 8. 证据、数据与审计

每项任务关联 task_id、子任务、标准版本、资料来源、执行记录、计时记录、用户证据、AI 审核、人工复核和最终交付物。

每份证据记录 evidence_id、task_id、文件/链接引用、类型、上传时间、来源说明、文件 hash、识别结果、对应标准、审核结论、审核理由和复核状态。

原始证据不可被 AI 静默覆盖；新证据追加版本，不覆盖历史审核；审核记录关联模型、时间、标准版本和引用。所有任务与证据按 user_id 服务端隔离，客户端传入 user_id 不可作为授权依据。

## 9. 视觉与交互规范

- 继承 V8 深色墨绿/航行主题、鸭子品牌符号和温暖金色点缀。
- 使用微信原生导航习惯、卡片式内容、明确层级、单屏一个主要动作。
- 关键字号优先 16px 及以上；辅助文字不低于 12px；点击区域至少 44px。
- 主色深墨绿/深青，强调色鸭子暖金；状态色仅表达成功、风险和错误。
- 表单先问最少必要信息；复杂任务分步引导，允许保存草稿。
- 反馈必须具体：正在发送、已发送、验证失败、待验收、部分通过、无法核验。
- 适配窄屏、安全区、键盘弹出、弱网、刷新和返回操作。

## 10. 核心数据对象

- User：id、phone_e164、phone_verified_at、password_hash、created_at、status。
- SmsChallenge：id、phone_e164、code_hash、purpose、expires_at、attempts、consumed_at、provider_status。
- Session：token_hash、user_id、expires_at、revoked_at、device_info。
- Task：id、user_id、title、type、goal、deadline、priority、state、estimate、actual_time。
- AcceptanceStandard：id、task_id、version、criteria、required、created_at、confirmed_at。
- Evidence：id、task_id、standard_id、file_ref、sha256、source、created_at。
- Review：id、task_id、evidence_ids、standard_version、result、reason、model_run_id、reviewed_at。
- ExecutionLog：id、task_id、started_at、ended_at、focus_state、blocker、output_ref。

手机号唯一索引；任务与证据按用户隔离。

## 11. 优先级与验收门

### P0：账号和真实闭环底座
- 手机号短信注册、首次设置密码、手机号密码登录、找回密码、退出。
- 旧账号手机号绑定迁移，不丢 V8 数据。
- 统一 task_id、验收标准版本、证据上传和审核记录。
- 口头完成不能直接通过。
- 手机端主要页面和基础导航。

### P1：执行教练
- 硬截止优先、固定事务保护、动态排期、精力反馈。
- 番茄钟、卡壳诊断、无产出预警、断点恢复。
- 今日驾驶舱、截止雷达和历史复盘。

### P2：学习督学
- 课程进度、笔记关联、知识测试。
- OCR 拍照做题、批改、错题本和订正复验。

### P3：增强与集成
- 摄像头辅助观察、多模态处理、授权资料读取。
- 微信收集、飞书、Obsidian、视频讲解和数据分析。

验收门：
- AUTH-1：同手机号只能注册一次；验证码错、过期、重放均不能注册。
- AUTH-2：真实手机收到验证码；服务端验证后才允许设置密码。
- AUTH-3：正确密码可登录，错误密码必拒绝；找回密码必须重新短信验证。
- AUTH-4：旧账号迁移后任务数、任务 ID、历史记录保持一致。
- TASK-1：口头说完成不改变验收通过状态。
- EVIDENCE-1：证据上传、识别、审核和历史版本可追溯。
- REVIEW-1：硬性标准缺失时不能被总分抵消。
- MOBILE-1：真机窄屏、键盘、弱网、刷新和返回流程可用。
- PRIVACY-1：摄像头默认关闭；短信密钥不出现在前端和仓库。
- TRAE-1：官方结营材料逐项有真实凭证，不能用模拟数据替代。

## 13. 最终产品承诺

不让计划上的完成代替现实中的完成；不让计时上的投入代替真正的产出；不让 AI 的口头判断代替真实证据。

让上岸鸭成为一个真正会安排、会督学、会发现问题、会教人解决问题、会检查成果的 AI 执行教练。
