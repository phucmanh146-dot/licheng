# DDL前三天兜底排期：复用现有 B 容量引擎

## 结论
本仓库已有可复用的确定性排程基础：`action_planner.py` 生成证据关联任务，`b_capacity.py` 计算单人真实空档、每日容量、缓冲和锁定时段，`b_joint_schedule.py` 计算多人共同空档、依赖和条件性倒推，`b_refinements.py` 处理拆分、锁定、校准、增量更新和备选方案。不要再造第二套日历。

## 需要补的策略层
新增 `ddl_sprint_policy.py` 作为调度前的确定性策略适配器：
1. 读取准确DDL、剩余分钟、重要性、工作量、任务模式、未来真实时间块。
2. 固定时间、每日固定和锁定任务受保护，不作为被挤占对象。
3. 在DDL前三天的 T-3 15:00 检查点，若任务尚未有足够的真实时间块，不回填T-3，而是将未安排分钟进入T-2强制兜底队列。
4. 排序：多且重要 → 少且重要 → 多且不重要 → 少且不重要；同象限再按DDL、剩余工作量排序。
5. T-2真实容量不足时返回显式冲突与三种人工决策：压缩、最多顺延一档、主动舍弃。不能自动删除，也不能无限顺延。
6. 里程碑预测不能冒充可执行时间块；只有正式时间块才能抵扣剩余工作。

## 与现有流程的接点
`任务录入 → AI/人工确认任务字段 → action_planner 生成任务 → T-3策略分类 → b_capacity / b_joint_schedule 计算真实时间块 → proposal预览 → 用户采用 → SQLite项目版本保存 → 执行反馈 → 增量reconcile`。

独立模块当前只负责分类和兜底队列/超载解释；它还没有被 `team.propose/apply` 或 `/api/agent/planner/replan` 自动调用。必须在服务端调度入口接入并增加端到端测试后，才能称为已联动。

## 验收
- T-3 15:00漏排任务下沉T-2，不回填T-3。
- 固定课表/每日固定投入/锁定时间不被移动。
- 只用真实时间块抵扣剩余工作。
- 四象限排序稳定。
- T-2超载时返回压缩/有限顺延/舍弃选择。
- 已完成、待验收、进行中和受保护任务不被静默覆盖。
- 每次采用生成版本差异和可恢复历史。
