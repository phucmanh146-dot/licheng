# 检索层设计

## 流水线
```text
学生原话 → 查询路由 → 查询重写 → 元数据过滤
        → BM25 + 向量检索 → RRF 融合 → 按画像组装
        → 碎片收件箱 + 打转告警
```

## 每步的证据与边界
- **查询路由**：报错/操作/概念/模糊四类；只有指代没有动作词时直接转澄清三问，不检索。
- **查询重写**：BM25 用聚焦后的关键词（报错类保留 `TypeError` 并补同义），向量路保留学生原话以保留语义上下文。重写只做同义扩展，不编造事实。
- **元数据过滤**：`难度 ≤ 画像理解档 + 0.1`（i+1）。越界资料默认移除；若无资料剩余，保留难度最低的一篇作为桥接材料。
- **混合检索**：BM25（k1=1.5, b=0.75）+ TF-IDF 余弦向量代理；生产替换为智谱 Embedding + FAISS 时只需实现 `vector_scores(query, docs) -> dict[doc_id, score]`。
- **RRF**：`Σ 1/(60 + rank)`，rank 从 1 起，两路各取 Top20。按排名融合而非分数，避免两路分数尺度不同。
- **按画像组装**：理解档 <0.34 输出“一句话结论 + 名词白话 + 类比 + 下一步只做一件事”；更高档位逐步增加操作要点与边界条件。
- **碎片收件箱**：`(theme, doc_id)` 哈希去重；同主题第 3 次查询触发换源告警（论文→文档→视频→问人）；权重 14 天半衰期，低于 0.1 自动淘汰。

## 复现命令
```bash
python -m app.retrieval.demo_retrieval   # 三个用户场景
python -m app.retrieval.eval_retrieval   # 9 条标注 query 的指标表
POST /api/agent/retrieve                  # 后端 API，带 query/profile/trace
```

`trace=true` 时返回路由置信度、两路 Top-K、RRF 分数、过滤原因和记忆写入结果，便于答辩现场逐层展示。
