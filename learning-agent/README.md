# 上岸鸭 · 联网学习导航 Agent

2026-10-12新增实际材料总调度，见[本轮代码与三人接入清单](../docs/general-agent-implementation-2026-10-12.md)。优化分支提供磁盘/拖入文件、项目与本人任务、能力试做分流、已配置模型诊断/复核、人工确认后的剩余计划预览。启动使用 `python learning_agent_server.py --port 8922 --with-team-ai --open-team`。模型绑定、工程检查和真实内容效果是不同验证阶段；当前结果以该记录为准。

这是给现有上岸鸭增加的 Python 后端与学习导航页面。它围绕“迷茫 → 查资料 → 小任务 → 验收 → 卡点救援 / 突发重排”工作，模型通过受约束的 JSON 工具协议决定继续搜索、读取来源或生成路线。

最新流程是 **你选择今天做什么，Agent 将选中的任务拆到具体动作，放进你提供的空闲时段**。详细的标准化流程和日程例子见 [WORKFLOW.md](WORKFLOW.md)。参考的抖音原视频页面已核实，但未取得完整字幕；该流程依据用户明确需求设计。

遇到困难可以直接点 **“卡住了？上传图片或视频”**：写一句现在卡在哪里，附截图或录屏，获得针对当前问题的解答、1–6个操作步骤、每步成功标志和失败后的检查方向。无需填写日程与截止日期。录屏可指定重点秒数；没解决时点“继续补图追问”，下一次请求会带上前一次解答与操作记录。

竞赛任务规划适用于用户实际参加的不同赛事：输入赛事名称、现有作品、目标、能力证据、分工和时间约束，得到能逐步执行与验收的路线。“挑战杯”只是说明流程的假设案例，PPT 只是可能的交付物；完整案例见 [通用定位与案例](../docs/competition-agent-example.md)。案例中的要求、材料和时间不会自动填入真实任务。

## 启动

需要 Python 3.10+。联网和任务功能使用标准库。字幕 MP4 另需 Pillow、包含 libx264 的 FFmpeg 和中文字体。

```bash
python -m pip install -r requirements.txt
python learning_agent_server.py --port 8901
```

打开 http://127.0.0.1:8901/learning-agent.html 。在“AI 连接”中配置已有服务，或用后端环境变量 `FOCUS_AI_BASE_URL`、`FOCUS_AI_MODEL`、`FOCUS_AI_API_KEY`。支持 Chat Completions 兼容协议、Responses 和 Anthropic，模型需能遵循 JSON 输出；分析图片另需模型支持视觉输入。不要把密钥提交到 Git。

联网搜索可设置 `TAVILY_API_KEY` 使用正式搜索接口；没有配置时尝试公开搜索页面。公开搜索可能被拒绝或没有结果，日志会如实提示，仍会读取用户提供的公开链接。竞赛模式按实际输入的赛事名称检索，不预置某场比赛的规则或获奖资料；学习模式保留下面的学习资料入口。当前验证环境的免费搜索没有返回结果，不能保证该兜底在部署环境可用。

在原 V9 目录中安装时，将新文件放到该目录，运行 `python install_local.py` 或双击 `启动学习导航Agent.cmd`。安装器备份原首页，仅插入入口脚本，在本机 8901 启动新进程；原来的 8879 服务和工作台任务数据保留。已有 `local_integrations.py` / `v9_server.py` 时沿用原后端的模型连接。独立使用无需这些私有集成文件。

## 能做什么

- 从目标、基础、每天可用分钟和截止日期出发，真实检索公开网页，读取可访问正文。每次运行保留搜索、阅读、模型规划、保存的事件记录。
- 竞赛模式要求填写实际赛事名称；已知的届次、年份、赛道一并填写，再用相应通知核对。页面不默认目标或截止日期，规划中保留赛事上下文，未核实的要求列为待确认事项。
- 预置用户指定的 [Agent 中文学习路线](https://github.com/WenyuChiou/awesome-agentic-ai-zh) 与 [Hello Agents](https://github.com/datawhalechina/hello-agents) 作为资料入口，实时读取，不把资源清单声称为已安装模型。
- 模型按需调用 `search` / `read`，最多七轮且最多四轮工具动作。生成的任务必须有工时估计、前置依赖、成果、验收标准、第一步和有效来源编号，失败可修正两次。
- SQLite 保存路线、运行记录、版本；刷新或重启可恢复已保存路线。服务重启时尚未完成的请求会标记中断，不伪装完成。
- 每个任务继续拆为动作：具体操作、预计分钟、成果与完成标志。第一步不超过 5 分钟，其余单步不超过 25 分钟。用户勾选每日任务并填写空闲时段后，才生成具体起止时刻表；缓冲时间保留，未选任务不自动塞入。
- 动作完成时记录证据与实际用时，完成所有动作后更新父任务。后端保留实际 / 预计用时统计，供下一次选任务参考。
- 插入临时任务、设置没空日期、改变每日容量，先预览再采用。确定性排程保证每日容量不超限和依赖顺序，已完成任务保持原记录。容量不足时返回明确冲突，不保证所有约束都有可行解。
- 截图或本地视频在浏览器转换成最多六张 JPEG 采样帧，再交给配置的视觉模型。视频音轨不分析，快速瞬间可能漏采；原视频及图片原始内容不进入 SQLite。
- 卡点模式先分析画面，再按需检索；不强行生成宏观学习路线或读取无关课程。搜索失败不阻断已有画面的解答，页面显示网络证据缺失。观察、推测和待补信息分开展示；画面编号必须存在，展示秒数由后端从实际上传帧读取。模糊或缺失信息要求补充，视觉调用失败不会伪装成看过图片。
- 后端用 Pillow + FFmpeg 生成真实 H.264 MP4 字幕讲解。每次先讲最多八个动作，明确显示覆盖数量；完整动作可在任务卡查看。它是可跟做的字幕视频，不是自动操作录屏，也不包含语音配音。Linux 可设置 `SHANGAN_AGENT_FONT` 指向已安装中文字体。

工作台与导航路线目前分别保存；导航任务在本页验收，不会自动把原工作台的其他任务标成完成。

## 科研与创新实践的真实成长闭环（本轮强化）

本项目的状态寄存器继续复用 SQLite 中的项目版本、材料版本、运行事件、诊断、计划、执行反馈和复核历史；不另建一套与 A/B/C 脱节的任务系统。

- **寄存器与刷新恢复**：项目版本、运行事件、V1/V2、卡点与复核结果持久化。刷新页面或重新打开服务后，应从已保存的项目/运行记录读取，不以浏览器里的临时状态作为完成依据。
- **有限循环**：研究 Agent 仍使用有上限的工具循环；相同搜索词/来源编号重复调用会被阻止并记入事件，避免无效消耗。每次工具调用与结果都留有可追踪事件。
- **上下文管理**：传给模型的来源上下文默认最多 12 个来源、最多 36,000 字符，每条来源最多 4,500 字符；只裁剪提示上下文，不修改证据登记簿中的原文。
- **跨会话意图恢复**：新增 `POST /api/agent/team/recover`，输入 `{"intent":"接着做上次科研项目的用户验证","sessionId":"new-session-id"}`。系统只在已有项目候选中做精确或模型辅助匹配；模型必须返回候选项目 ID 且置信度至少 0.62。没有足够依据时返回候选列表，不自动猜项目。匹配后仍需用户确认，不会自动改写任务状态。
- **工具调用**：来源必须先登记，再按真实来源编号读取；失败保留失败事件，模型不可以把搜索摘要说成已读正文。
- **A→B 证据门**：已核验/已绑定证据的差距需要当前作品版本、准确位置、现状证据、可复用方法说明，以及真实微动作；外部参考若被标为 reference，还必须提供原始页/段/章节/代码定位。
- **B→执行人行动门**：生产任务没有 A 给出的 grounded `micro_steps` 时会进入 `blocked/unscheduled`，明确缺什么，不再用“打开材料→完成成果→检查”通用三步冒充可执行计划。
- **C→A→B 复核门**：真人提交 V2 后只能进入待复核；A 按原判据返回 pass/fail/unknown，B 只处理剩余问题。没有真实 V2 与复核记录，不宣称成长闭环完成。

新增回归测试：
`python -m unittest -v test_action_planner.py test_team_recovery.py`
以及 `test_general_loop.py` 中的提示上下文预算测试。模拟模型测试只验证协议、状态和边界，不替代真实模型质量或真人照卡执行验收。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/agent/health` | 后端与模型配置状态（配置不等于本轮调用已成功） |
| `POST /api/agent/run` | 提交目标；竞赛模式先校验实际赛事名称，通过后返回 runId，后台联网 / 规划 |
| `GET /api/agent/run?id=…` | 运行状态和真实事件 |
| `GET /api/agent/state` | 保存的路线与最近运行 |
| `POST /api/agent/replan` | 预览重排；`apply:true` 保存，校验版本 |
| `POST /api/agent/complete` | 校验前置任务并保存完成证据 |
| `POST /api/agent/day` | 用户选择任务及空闲时段后，预览 / 采用具体日程 |
| `POST /api/agent/action` | 逐动作保存验收结果与实际用时 |
| `POST /api/agent/undo` | 恢复上一版本，产生新版本记录 |
| `POST /api/agent/tutorial` | 生成 / 获取对应路线版本的 MP4 |

`mode:"competition"` 必须提供非空的 `competitionName`（去除首尾空格后 1–200 字），可在名称中附届次、年份和赛道。缺失或无效时返回 400，不创建运行任务；学习和卡点模式不要求此字段。`competitionName` 随检索、模型上下文和保存路线一起保留，截止日期未确认可留空。

默认只监听 127.0.0.1，校验 Host / Origin；只抓公开 HTTP(S) 地址，拒绝内网 IP 和非法跳转。模型工具不会执行网页指令、任意 Python、终端命令或自动发送消息。生成视频的命令参数固定，用户文字只渲染为图像。

不是面向互联网的多用户服务：公开部署前还需要用户身份认证、数据隔离、作业队列和对象存储。不要直接把本地服务绑定公网。Vercel 云端部署应另外适配持久化和后台任务，不能直接复制 SQLite / FFmpeg 服务并宣称可用。

## 验证

```bash
python -m unittest -v test_agent.py test_competition_context.py
```

覆盖容量、依赖顺序、截止冲突、已完成进度、循环依赖、来源引用、图片输入、乐观锁、预览不写入与撤销。工具循环协议测试明确使用模拟网络和模型，不能替代真实联网 / 模型调用验证。实际环境验收记录见 `VERIFICATION.md`。

`node test_rescue_ui.cjs` 检查真实浏览器的图片转换、视频抽帧、重点秒数、追问上下文以及 SQLite 保存边界。它使用本机模拟视觉接口检查数据传递，不验证模型实际理解画面的能力。

2026-10-11 的竞赛通用化修改已通过 32 项 Python 测试，新增 5 项覆盖赛事输入校验、不同赛事的独立检索、用户链接读取、赛事上下文保存，以及同一秒保存多条路线时的恢复顺序。路线与运行列表为同时间记录增加确定的排序，避免刷新后误选上一条路线。

Chrome 145 浏览器验收已通过 26 项流程检查：`node test_competition_browser.cjs` 的 6 项（示例不回填、缺失赛事阻止提交、赛事传递、独立来源与刷新恢复、模式切换、移动端不溢出），原日程界面 10 项及卡点界面 10 项。日程脚本刷新后显式选择测试日期，不再依赖运行当天；字幕视频验收配置了中文字体，生成并探测到 42 秒 MP4。检索与模型回答使用明确标注的人工夹具，这些检查验证真实页面、HTTP 和 SQLite 数据流，不代表真实赛事材料解析质量、视觉理解质量或真实用户验收。

原始后端资料读取与模型适配模块取自用户自己的 V9 项目，本次新增的编排、排程、持久化、视频与页面为独立模块。运行数据在 `.learning-agent/`，不提交 Git。
