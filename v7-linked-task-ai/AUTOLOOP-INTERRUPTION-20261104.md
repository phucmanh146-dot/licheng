# 上岸鸭 Autoloop：突发事件接管与弹性排期（2026-11-04）

## 目标

用户只需在现有“快速收集”入口上传截图/文档或粘贴通知，系统识别时间块；遇到临时课程、会议、考试等固定事务时，保存当前任务现场、暂停计时、锁定固定安排，并仅重排可移动任务。用户不需要重新填写原任务，也不需要逐项确认普通重排结果。

## 设计原则

1. **零消耗挂起**：等待课程/会议期间不运行模型轮询；只保存状态并停止当前计时。恢复时读取检查点，不重新生成整份计划。
2. **事件溯源**：事件表只允许追加，记录中断、恢复、导入和重排；检查点保存可恢复的任务快照。
3. **幂等**：同一份时间表根据账号、日期、起止时间和任务标题生成稳定事件 ID；重复上传不会重复创建相同任务。
4. **固定与弹性分离**：会议、开会、班会、讨论、必须事项、考试、面试、直播、休息/睡觉等识别为锁定时段；普通学习/练习时间作为可移动任务。
5. **缓冲优先**：排期只处理未来三天；每日按可用时长的 80% 安排任务，保留 20% 缓冲；任务间至少留 10 分钟；最晚安排到 23:45，不侵占 24:00 睡眠边界。
6. **不静默牺牲硬截止**：固定时间冲突或容量不足时不覆盖固定安排，将任务标记为“待安排”并在一条汇总提示中说明。
7. **数据与指令分离**：上传内容仅作为待识别资料，不作为 Agent 指令；本轮时间表识别和重排由本地确定性逻辑完成，不调用模型。

## 交互

- 在原快速收集面板增加“自动识别并接管排期”按钮。
- 图片/文档读取沿用原有资料读取入口；识别到时间段后显示识别数量。
- 点击一次即可导入整张时间表；无时间块时，调用原有任务识别和排程流程，不要求手动逐项填写。
- 接管时自动暂停正在运行的任务计时，保存活动任务 ID、任务列表、精力/日容量配置和检查点。
- 课程/会议锁定；普通学习块可在三天窗口内移动；20% 缓冲和 10 分钟间隔保留。
- 只显示一条汇总通知，提供“接着原任务”和“知道了”；恢复时合并缺失任务，不覆盖本机更新较新的任务记录。

## API

- `GET /api/autoloop/state?accountId=...`：读取检查点、事件和未恢复中断。
- `POST /api/autoloop/interrupt`：原子保存中断检查点并追加中断事件。
- `POST /api/autoloop/checkpoint`：保存当前任务快照。
- `POST /api/autoloop/event`：追加幂等事件。
- `POST /api/autoloop/resume`：返回检查点并追加恢复事件。

SQLite 位于每个 worker 的 `SHANGANYA_SESSION_HOME/autoloop.sqlite3`，按 worker/账号隔离；本地浏览器离线时先写入该账号的 localStorage 备用队列，网络恢复后按事件 ID 幂等同步。

## 验收

- Python 单元测试：账号隔离、事件幂等、检查点恢复、恢复后清除待处理中断、事件不可更新/删除、非法事件拒绝。
- JavaScript 解析测试：普通任务块保持可移动；会议识别为固定；标题中的“11月2日/11月3日/11月4日”不会误改整张表的日期；24:00 睡眠边界识别为固定时段。
- HTTP 冒烟测试：状态读取 → 中断保存 → 待处理中断出现 → 恢复检查点 → 待处理中断清零。

## 当前边界

- 只有识别到明确的开始—结束时间，才能自动锁定临时课程/会议；缺少时间的通知不会猜测时段。
- OCR/文档文本读取复用现有快速收集能力；实际识别效果仍取决于上传文件质量及原读取模块支持的格式。
- 目前重排使用确定性规则，不调用 AI；尚未接入学校课表/日历的自动订阅，也不代表已经在 Railway 生产环境部署。
- 这次改动不删除原有 V8 导航、任务资料或用户数据。
