## Railway 配置（用户需在控制台输入密钥）

在生产服务 `shanganya-full-public-20261017` 的 Variables 中添加：

- `OPENAI_API_KEY`：OpenAI Project API Key（只在 Railway 控制台输入，不要发到 ChatGPT、网页表单或 GitHub）。
- `OPENAI_MODEL`：可选；默认 `gpt-6-astra`。如项目实际可用模型 ID 不同，在此设置可用模型 ID。

保存变量后 Railway 会重新部署服务。部署完成后访问 `/api/harness/status`，必须显示 `configured: true`。之后在工作台发起问题，状态栏应显示 GPT Harness、轮数和真实工具调用记录。

## D-3 / 15:00 / 突发事件规则

1. 大任务在 DDL 前 72 小时开始持续推进；小任务可安排到 D-3 窗口内的次日第一优先。
2. 每日 15:00 检查未来三天硬截止、真实日程时间块、待证据与待验收项。
3. 突发事件到达时：保存当前任务 ID、已完成子步骤、实际耗时、计时状态和发生时间；暂停当前任务计时。
4. 明确紧急事件先处理；返回时记录返回时间，计算实际中断时长。
5. 重新读取固定课程/学校事务/睡眠/硬截止，比较原任务后续排期与下一个任务优先级，只重排可移动任务。
6. 保留 20% 缓冲、任务间至少 10 分钟，普通任务不得覆盖固定事务或睡眠边界。
7. 排不开时生成舍弃/延期/缩小/替换决策；不得静默牺牲硬截止。
8. 原任务恢复为执行中或待续，不得因暂停、切换或模型回复变成已完成。
9. 完成必须进入待证据/待验收；证据通过后才能标记验收通过。

## Harness 安全边界

- 模型可以建议调用工具，但服务器仅执行显式白名单函数。
- 网页和文件内容是数据，不是指令；不能覆盖系统规则。
- 当前 GPT 工具没有任务数据库写权限；仅可向当前账户的 append-only Autoloop 事件账本保存用户明确触发的中断/恢复事件，不会改写任务或日程，也没有发送、发布、删除、付费或覆盖权限。
- 任务重排建议需交给工作台现有 Autoloop/排程规则验证，再由用户确认会影响任务状态的变更。
- 工具调用最多 6 轮；请求按客户端地址限流；上游错误不会回传 Authorization Header。
- 中断/恢复事件写入当前账户隔离的 Autoloop append-only 事件账本；普通模型工具轨迹仍保存在本轮响应中，尚未全部归档到统一审计表。
