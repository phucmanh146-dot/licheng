# 上岸鸭｜任务真实性验收与固定评分规范
版本：2026-11-01

## 1. 用户明确提出的核心问题
- 点击“停止”是用户主观操作，不代表真实活动已经停止。
- 点击“完成”或本人汇报“做完了”不能作为唯一完成依据；自我汇报容易造假。
- 不同任务不能共用一个简单勾选框，必须按任务类型采用对应验收方法。
- 同一任务必须使用同一套固定评分细则，不能每次由 AI 临时发挥、同一作品不同时间/不同人评分差异巨大。
- 任务是否完成、交付物质量、知识是否掌握、是否实际提交，是不同状态，必须拆开记录。
- PPT 不要求等待专家组最终评审；应按预先确定的评分细则逐项检查、逐项打分，输出分数和缺项。

## 2. 历史聊天中确认的运营流程
- 每日运营两个抖音账号；运营方向与账号主页须先核实，不能把旧“醒图”项目自动恢复。
- 每天先检查上一次真实执行记录，再确认当日账号、主题、受众和交付物。
- 运营任务拆为五步：资料读取与选题核验、脚本标题与分镜、拍摄/录屏与剪辑、发布前质量与合规核验、发布与数据回填。
- 保留来源链接、原文/正文读取状态、时间、任务交付物和证据；仅保存链接不等于已读取。
- 作品发布必须有真实作品链接；后台数据必须有真实截图/凭证；不得虚构播放量、完播率、点赞、收藏或发布状态。
- 旧醒图项目已停止，仅作历史资料归档；不得将旧流程、旧账号或旧奖励规则误当作当前运营任务。
- 不得自动化刷浏览、关注、点赞、评论或抓取私密数据；发布由账号本人确认。
- 数据归用户所有；不设置账号/密码。
- 每日08:00核验今日计划；DDL前三天启动保护；14:00检查今日已排但未启动的任务；硬截止、固定事务优先，不能让运营挤占学校作业、比赛和训练营交付。
- 任务开始、任务完成、已提交、删除必须分开；计划已安排不等于实际已执行。

## 3. 分类型验收
### 行为/停止任务
- 证据：计时事件、窗口前台/焦点变化、应用活动事件、任务切换记录。
- 屏幕/窗口活动只能作为行为代理信号，不能证明用户生理或心理上停止工作。
- 若没有可用设备事件或授权监测，标记“行为待核验”，不把按钮点击当成真实停止。

### 课程学习
- 课程进度/章节记录证明学习过程，不证明掌握。
- 另行生成基于课程内容的独立测试，记录题目、答案、正确率和错题。
- 没有平台学习记录时标“播放进度待核验”；不能仅凭自述认定听完。

### PPT/文档
- 按固定评分表检查要求覆盖、逻辑结构、内容与证据、表达视觉、交付规范。
- 输出每项得分、扣分理由、证据位置、返工项和总分。
- 不依赖专家组最终评分才给内部过程分；内部评分不能冒充专家组评分。

### 代码/网页
- 检查代码/版本证据、功能逐项实现、真实运行、异常边界、回归和交付说明。
- 静态检查不等于运行验收；部署链接能打开也不等于所有功能通过。

### 视频运营
- 检查真实成片、画幅/清晰度、声音、字幕、内容真实性与完整性。
- 发布验收要求真实作品链接；后台数据验收要求截图或可验证凭证。
- HeyGen演示、AI生成画面不能冒充真实醒图操作录屏。

## 4. 统一状态机
待执行 → 执行中 → 待验收 → 部分通过/返工中 → 已验收完成。
另设：行为待核验、知识待验证、提交待核验。
“文件已生成”“课程已播放”“用户点完成”“平台已提交”分别记录，不混为一谈。

## 5. 固定评分机制
- 评分表带版本号；同一类型同一版本使用同一权重和评分锚点。
- 每个评分项必须有证据位置/链接/文件名/检查结果；没有证据不得得分。
- 0分=无证据/未完成；50%=部分符合；100%=符合。
- 总分按固定权重自动计算；≥80分且所有评分项均有证据，标记“评分通过”；否则部分通过/未通过并列出缺项。
- 自填证据只是待核验材料，不代表独立验证。平台数据、课程进度、文件内容和运行结果需通过相应真实来源核验。
- 评分结果与任务完成状态分离，评分通过后仍须满足对应交付/提交条件才可进入最终完成。
